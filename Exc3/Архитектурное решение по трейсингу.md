# 3. Архитектурное решение по трейсингу

## системы, которые следует покрыть трейсингом

- Прием заказа shop api
- Прием заказа crm api
- Добавление crm api заказа в очередь RabbitMQ
- Прием и изменение заказа mes api

## список данных, которые должны попадать в трейсинг
- идентификатор заказа
- временная метка
- статус заказа
- идентификатор заказчика
- идентификатор инициатора действия

## Мотивация
Для компании трейсинг позволит:
- ускорит локализацию и устранение проблем (улучшение пользовательского опыта)
- уменьшит трудозатраты ops подразделения (оптимизация ФОТ)
- даст информацию для планирования дальнейшего развития системы (повышение управляемости системы)
- позволит определить четкие характеристики системы (поэтапное время обработки заказов)

## Предлагаемое решение
В компоненты shop api, crm api, mes api необходимо интегрировать код трейсинга на базе opentelemetry
Необходимо развернуть Jaeger для осуществления централизованного сбора трейсов от всех компонент.
Необходимо развернуть Jaeger UI с помощью которого сотрудники смогут изучать трейсы.

## Компромиссы
Код трейсинга необходимо интегрировать в логику компонент, что может потребовать значительных ресурсов.
В проекте весь код является собственностью компании, при этом в команде разработки есть компетенция необходимая для внесения изменений.

## Аспекты безопасности. 
Встроенная аутантификация Jaeger позволит обеспечить доступ к трейсам только административного персонала
